\section{Thiết kế API}

Hệ thống SmartDroneDelivery cung cấp giao diện lập trình ứng dụng (API) theo kiến trúc RESTful, cho phép Web Application, Mobile Application và các hệ thống bên thứ ba tương tác với dữ liệu và nghiệp vụ của nền tảng.

Toàn bộ API được xây dựng trên nền tảng Flask, tuân theo kiến trúc phân lớp (Controller - Service - Repository), đảm bảo tính mở rộng và dễ bảo trì. Dữ liệu trao đổi giữa client và server được định dạng theo chuẩn JSON.

\begin{itemize}
\item
  \textbf{Base URL hiện tại:} \texttt{http://localhost:5000} trong môi trường phát triển; frontend hiện cấu hình cùng địa chỉ này.
\item
  \textbf{Định dạng dữ liệu:} JSON (Content-Type: application/json)
\item
  \textbf{Xác thực:} JSON Web Token (JWT), được truyền qua header \texttt{Authorization: Bearer <token>} đối với các endpoint yêu cầu đăng nhập
\item
  \textbf{Mã trạng thái phản hồi:} Tuân theo chuẩn HTTP (200 - Thành công, 201 - Tạo mới thành công, 400 - Yêu cầu không hợp lệ, 401 - Chưa xác thực, 404 - Không tìm thấy tài nguyên, 500 - Lỗi hệ thống)
\end{itemize}

\subsection{Quy ước request và response}

Các endpoint sử dụng JSON nhưng response hiện chưa có envelope thống nhất. Tùy controller, API có thể trả object, array hoặc object chứa trường \texttt{message}; tài liệu này mô tả theo payload thực tế thay vì giả định mọi response đều có trường \texttt{data}.

\begin{verbatim}
{
  "data": { "id": 24, "status": "APPROVED" },
  "message": "Request processed successfully"
}
\end{verbatim}

Đối với lỗi xác thực hoặc dữ liệu không hợp lệ, API trả về mã HTTP tương ứng. Phân trang, tìm kiếm và lọc chưa được triển khai đồng nhất cho tất cả API danh sách; frontend hiện lọc cục bộ ở một số màn hình.

\subsection{Phân quyền API}

Một số controller đã dùng JWT hoặc decorator kiểm tra quyền, nhưng việc bảo vệ route chưa đồng nhất giữa các module. Audit log đầy đủ chưa được triển khai; không nên xem các quy tắc phân quyền trong mục này là đã hoàn thành cho toàn bộ API.

\subsection{Đối chiếu API phiên bản hiện tại}

Bảng endpoint ở trên là danh sách nghiệp vụ chính. Danh sách triển khai thực tế còn bao gồm các nhóm sau:

\begin{itemize}
  \item \textbf{Người dùng và phân quyền:} \texttt{GET /api/users}, \texttt{GET/PUT /api/users/profile}, \texttt{GET/POST /api/roles}, \texttt{GET /api/functions}, \texttt{POST /api/roles/<id>/functions}.
  \item \textbf{Đơn hàng:} \texttt{GET /api/orders}, các thao tác \texttt{approve}, \texttt{reject}, \texttt{schedule}, \texttt{complete}, \texttt{fail} và \texttt{retry}.
  \item \textbf{Drone và trạm:} CRUD \texttt{/api/drones}, xác nhận quay về; CRUD \texttt{/api/stations}, cập nhật trạng thái và xem sức chứa.
  \item \textbf{Kiện hàng:} \texttt{/api/package-receipts}, cập nhật trạng thái và xem timeline kiện hàng.
  \item \textbf{Thông báo và hệ thống:} đọc/đánh dấu đã đọc thông báo và \texttt{GET /api/health}.
  \item \textbf{Analytics và AI:} năm endpoint analytics, ETA, chatbot và tóm tắt giao hàng.
\end{itemize}

Các controller hiện trả response JSON trực tiếp theo từng endpoint; chưa áp dụng thống nhất envelope dạng \texttt{\{data, message\}} cho toàn bộ API. Vì vậy client phải xử lý cả object, array và response có trường \texttt{message} tùy nhóm chức năng.

Các route nghiệp vụ mới hoặc thay đổi phương thức phải được đối chiếu với controller trước khi cập nhật tài liệu. Cụ thể, approve/reject hỗ trợ PUT/PATCH, schedule hỗ trợ POST/PUT, complete hỗ trợ PUT/PATCH và fail/retry hỗ trợ POST/PUT/PATCH.

\subsection{Nhóm API Xác thực và Người dùng}

\subsubsection{Đăng ký tài khoản}

\begin{itemize}
\item
  \textbf{Endpoint:} POST /api/auth/register
\item
  \textbf{Mô tả:} Tạo tài khoản mới cho khách hàng, tự động gán vai trò mặc định là Customer.
\item
  \textbf{Tham số đầu vào (Request Body):}
\end{itemize}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\item
  email (chuỗi, bắt buộc): Địa chỉ email dùng để đăng nhập
\item
  password (chuỗi, bắt buộc): Mật khẩu tài khoản
\item
  full\_name (chuỗi, tùy chọn): Họ tên đầy đủ của người dùng
\end{enumerate}

\begin{itemize}
\item
  \textbf{Kết quả trả về:} Thông tin định danh (id) của tài khoản vừa tạo.
\item
  \textbf{Điều kiện lỗi:} Email đã tồn tại trong hệ thống; thiếu email hoặc mật khẩu; chưa cấu hình vai trò Customer trong hệ thống.
\end{itemize}

\subsubsection{Đăng nhập}

\begin{itemize}
\item
  \textbf{Endpoint:} POST /api/auth/login
\item
  \textbf{Mô tả:} Xác thực tài khoản và cấp phát mã truy cập (access token) sử dụng cho các yêu cầu tiếp theo.
\item
  \textbf{Tham số đầu vào:} email, password
\item
  \textbf{Kết quả trả về:} access\_token và thông tin cơ bản của người dùng (id, email, họ tên, vai trò).
\item
  \textbf{Điều kiện lỗi:} Email hoặc mật khẩu không đúng; tài khoản đã bị khóa.
\end{itemize}

\subsubsection{Đăng xuất}

\begin{itemize}
\item
  \textbf{Endpoint:} POST /api/auth/logout
\item
  \textbf{Mô tả:} Kết thúc phiên làm việc hiện tại của người dùng đã xác thực.
\item
  \textbf{Header bắt buộc:} \texttt{Authorization: Bearer <access\_token>}
\item
  \textbf{Kết quả trả về:} HTTP 200 và thông báo ``Đăng xuất thành công''. Client phải xóa access token và dữ liệu phiên cục bộ sau khi nhận response.
\item
  \textbf{Điều kiện lỗi:} Thiếu token, token hết hạn hoặc token không hợp lệ; API trả về lỗi xác thực tương ứng.
\end{itemize}

\subsubsection{Quên mật khẩu và đặt lại mật khẩu}

\begin{itemize}
\item
  \textbf{Endpoint:} POST /api/auth/forgot-password
\item
  \textbf{Mô tả:} Sinh mã xác nhận và gửi đến email của người dùng để phục vụ việc đặt lại mật khẩu.
\item
  \textbf{Endpoint tiếp theo:} POST /api/auth/reset-password
\item
  \textbf{Tham số đầu vào:} token (mã xác nhận), new\_password (mật khẩu mới)
\item
  \textbf{Điều kiện lỗi:} Mã xác nhận không hợp lệ hoặc đã hết hạn (hiệu lực 15 phút).
\end{itemize}

\subsubsection{Quản lý hồ sơ cá nhân}

\begin{itemize}
\item
  \textbf{Endpoint:} GET, PUT /api/users/profile
\item
  \textbf{Mô tả:} Cho phép người dùng đã đăng nhập xem và cập nhật thông tin cá nhân (họ tên, số điện thoại).
\item
  \textbf{Yêu cầu:} Bắt buộc xác thực bằng JWT.
\end{itemize}

\subsection{Nhóm API Địa chỉ và Khách hàng}

\subsubsection{Quản lý địa chỉ giao hàng}

Nhóm API này cho phép tạo, xem, cập nhật và xóa các địa chỉ giao hàng liên kết với khách hàng.

\begin{itemize}
\item
  \textbf{Tạo địa chỉ:} POST /api/addresses -- Tham số: street, city, latitude, longitude.
\item
  \textbf{Xem danh sách địa chỉ:} GET /api/addresses.
\item
  \textbf{Cập nhật địa chỉ:} PUT /api/addresses/<id>.
\item
  \textbf{Xóa địa chỉ:} DELETE /api/addresses/<id>.
\end{itemize}

\subsubsection{Quản lý thông tin khách hàng}

\begin{itemize}
\item
  \textbf{Xem thông tin:} GET /api/customers/<id> -- Trả về họ tên, số điện thoại, địa chỉ liên kết.
\item
  \textbf{Cập nhật thông tin:} PUT /api/customers/<id> -- Cho phép cập nhật họ tên, số điện thoại và địa chỉ.
\item
  \textbf{Điều kiện lỗi:} Không tìm thấy khách hàng với id được cung cấp.
\end{itemize}

\subsection{Nhóm API Trạm giao hàng}

Nhóm API này phục vụ việc quản lý các trạm hạ cánh của drone, bao gồm vị trí, sức chứa và trạng thái vận hành.

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\item
  \textbf{Tạo trạm mới} (POST /api/stations): Nhập tên trạm, tọa độ (vĩ độ, kinh độ), sức chứa tối đa và trạng thái ban đầu.
\item
  \textbf{Xem danh sách và chi tiết trạm} (GET /api/stations, GET /api/stations/<id>).
\item
  \textbf{Cập nhật thông tin trạm} (PUT /api/stations/<id>): Cho phép chỉnh sửa tên, vị trí, sức chứa.
\item
  \textbf{Xóa trạm} (DELETE /api/stations/<id>).
\item
  \textbf{Cập nhật trạng thái và vị trí trạm} (PUT /api/stations/<id>/status): Chuyển đổi trạng thái trạm giữa các giá trị hợp lệ (ví dụ: ACTIVE, MAINTENANCE). Hệ thống kiểm tra tính hợp lệ của trạng thái trước khi cập nhật.
\item
  \textbf{Xem sức chứa hiện tại} (GET /api/stations/<id>/capacity): Trả về sức chứa tối đa, số đơn hàng đang được gán cho trạm và số chỗ còn trống, được tính toán dựa trên dữ liệu đơn hàng thời gian thực.
\end{enumerate}

\subsection{Nhóm API Đơn hàng và Kiện hàng}

Nhóm API này hỗ trợ nghiệp vụ duyệt đơn, từ chối đơn và lập kế hoạch giao hàng, tương ứng với các yêu cầu chức năng FR-12, FR-13 và FR-14.

\subsubsection{Duyệt và từ chối đơn hàng}

\begin{itemize}
\item
  \textbf{Duyệt đơn:} PUT /api/orders/<id>/approve -- Chuyển trạng thái đơn hàng từ PENDING sang APPROVED.
\item
  \textbf{Từ chối đơn:} PUT /api/orders/<id>/reject -- Chuyển trạng thái đơn hàng sang REJECTED.
\item
  \textbf{Điều kiện lỗi:} Không tìm thấy đơn hàng với id được cung cấp.
\end{itemize}

\subsubsection{Lên lịch giao hàng}

\begin{itemize}
\item
  \textbf{Endpoint:} POST /api/orders/<id>/schedule
\item
  \textbf{Tham số đầu vào:}
\end{itemize}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\item
  scheduled\_time (chuỗi định dạng ISO 8601, bắt buộc): Thời gian dự kiến giao hàng
\item
  station\_id (số nguyên, tùy chọn): Trạm được gán để thực hiện giao hàng
\end{enumerate}

\begin{itemize}
\item
  \textbf{Mô tả xử lý:} Hệ thống cập nhật thời gian giao hàng dự kiến, gán trạm (nếu có) và chuyển trạng thái đơn hàng sang SCHEDULED.
\item
  \textbf{Điều kiện lỗi:} Thiếu tham số scheduled\_time; không tìm thấy đơn hàng; trạm được chỉ định không tồn tại.
\end{itemize}

\subsection{Nhóm API Tích hợp Trí tuệ nhân tạo}

Nhóm API này khai thác mô hình ngôn ngữ Gemini nhằm nâng cao trải nghiệm người dùng thông qua các tính năng dự đoán và hỗ trợ tự động.

\subsubsection{Ước tính thời gian giao hàng (ETA)}

\begin{itemize}
\item
  \textbf{Endpoint:} POST /api/eta/estimate
\item
  \textbf{Tham số đầu vào:} origin\_lat, origin\_lng, dest\_lat, dest\_lng (tọa độ điểm đi và điểm đến), speed\_kmh (tùy chọn, mặc định 40 km/h).
\item
  \textbf{Phương pháp tính toán:} Khoảng cách giữa hai điểm được tính theo công thức Haversine, sau đó suy ra thời gian di chuyển dựa trên tốc độ trung bình của drone.
\item
  \textbf{Kết quả trả về:} Khoảng cách (km), thời gian ước tính (phút), và một đoạn diễn giải bằng ngôn ngữ tự nhiên do AI sinh ra.
\item
  \textbf{Cơ chế dự phòng:} Trong trường hợp dịch vụ AI gặp sự cố, hệ thống vẫn trả về kết quả tính toán theo công thức, kèm theo thông báo mặc định thay cho phần diễn giải của AI.
\end{itemize}

\subsubsection{Trợ lý hội thoại (Chatbot)}

\begin{itemize}
\item
  \textbf{Endpoint:} POST /api/chatbot/ask
\item
  \textbf{Tham số đầu vào:} question (câu hỏi của khách hàng)
\item
  \textbf{Mô tả xử lý:} Câu hỏi được kết hợp với ngữ cảnh nghiệp vụ và gửi đến mô hình Gemini để sinh câu trả lời phù hợp, thân thiện, bằng tiếng Việt.
\item
  \textbf{Cơ chế dự phòng:} Nếu dịch vụ AI không phản hồi, hệ thống trả về thông báo hướng dẫn khách hàng liên hệ tổng đài hỗ trợ.
\end{itemize}

\subsubsection{Tóm tắt trạng thái giao hàng}

\begin{itemize}
\item
  \textbf{Endpoint:} POST /api/deliveries/summarize
\item
  \textbf{Tham số đầu vào:} order\_id, status\_history (danh sách các mốc thời gian và trạng thái của đơn hàng)
\item
  \textbf{Mô tả xử lý:} Lịch sử trạng thái được tổng hợp và gửi đến AI để sinh ra một đoạn tóm tắt ngắn gọn, dễ hiểu, giúp khách hàng nắm được tiến độ giao hàng hiện tại.
\item
  \textbf{Cơ chế dự phòng:} Nếu AI không khả dụng, hệ thống trả về trạng thái gần nhất của đơn hàng dưới dạng văn bản đơn giản.
\end{itemize}

\subsubsection{Thống kê vận hành (Analytics)}

\begin{itemize}
\item
  \textbf{Endpoint:} GET /api/analytics/orders-by-status
\item
  \textbf{Mô tả:} Cung cấp số liệu thống kê tổng số đơn hàng và số lượng đơn hàng phân theo từng trạng thái (PENDING, APPROVED, REJECTED, SCHEDULED), phục vụ nhu cầu theo dõi vận hành của quản lý logistics.
\item
  \textbf{Kết quả trả về:} Tổng số đơn hàng và một đối tượng thể hiện số lượng đơn hàng tương ứng với mỗi trạng thái.
\end{itemize}
